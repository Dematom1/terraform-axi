# New AXI tool: launch checklist

This is the copy-ready document for `docs/new-axi-tool-checklist.md`. Complete every applicable item before the first feature PR is considered ready. Mark a genuinely inapplicable item with a short reason; do not silently omit it.

## Principles/output

- [ ] **P1 — TOON only:** Every data-bearing stdout result—including errors, hints, help lists, and string-valued command results—uses valid TOON. Do not print raw strings or mix unstructured output into command responses; only the documented version probe may be a bare version string. **Why:** raw string and malformed help output escaped earlier audits ([argocd-axi #9](https://github.com/Dematom1/argocd-axi/pull/9), [#21](https://github.com/Dematom1/argocd-axi/pull/21), [#27](https://github.com/Dematom1/argocd-axi/pull/27); [argo-workflows-axi #18](https://github.com/Dematom1/argo-workflows-axi/pull/18), [#20](https://github.com/Dematom1/argo-workflows-axi/pull/20), [#24](https://github.com/Dematom1/argo-workflows-axi/pull/24); [datadog-axi #19](https://github.com/Dematom1/datadog-axi/pull/19), [#24](https://github.com/Dematom1/datadog-axi/pull/24)). **How to verify:** run every command/help/error path and decode every data-bearing stdout payload with a TOON parser; grep for direct stdout writes and exercise them.
- [ ] **P2 — Minimal schemas:** Default list output contains only the few fields needed to select or act on a result (target 3–4); provide an explicit expansion route for more detail. **Why:** the AXI contract prioritizes token-efficient selection over dumping API objects ([AXI principles](https://github.com/kunchenguid/axi#the-10-principles)). **How to verify:** inspect every list default and assert its field set and row cap in CLI tests.
- [ ] **P3 — Bounded output:** Bound rows and long text, report original size/count and truncation, and provide a working `--full` escape hatch wherever truncation occurs. **Why:** [argocd-axi #18](https://github.com/Dematom1/argocd-axi/pull/18) and [argo-workflows-axi #18](https://github.com/Dematom1/argo-workflows-axi/pull/18) established recovery previews; an unredacted raw escape hatch needed human-only warnings ([argo-workflows-axi #1](https://github.com/Dematom1/argo-workflows-axi/pull/1)). **How to verify:** feed oversized rows/details/logs and confirm bounded default, size metadata, and complete `--full` output.
- [ ] **P4 — Aggregates:** Include useful totals and status counts in list/home results, distinguishing known values from unknown values. **Why:** a missing incident count rendered as zero and understated state ([datadog-axi #32](https://github.com/Dematom1/datadog-axi/pull/32)); incomplete collection metadata was also corrected ([datadog-axi #11](https://github.com/Dematom1/datadog-axi/pull/11)). **How to verify:** test present, zero, missing, malformed, and partial API totals; unknown must never become zero.
- [ ] **P5 — Truthful states:** Emit explicit zero-result states; distinguish empty from unavailable, malformed, unauthorized, and partially returned data. **Why:** Datadog exposed false-zero and incomplete-search cases ([datadog-axi #11](https://github.com/Dematom1/datadog-axi/pull/11), [#32](https://github.com/Dematom1/datadog-axi/pull/32)); Argo Workflows rejected malformed list responses rather than claiming an empty collection ([argo-workflows-axi #11](https://github.com/Dematom1/argo-workflows-axi/pull/11)). **How to verify:** inject empty, missing, malformed, denied, and unavailable responses and assert distinct TOON states and correct exit codes.
- [ ] **P6 — Safe, retryable operations:** Mutations are idempotent or accept a stable retry/idempotency key; require a preview followed by explicit `--confirm`; default to read-only and require explicit writable-target opt-in, with one target selected by default. Refuse unknown/malformed flags and make errors structured with consistent exit codes. **Why:** Argo CD write commands added preview/confirmation and target gating ([argocd-axi #20](https://github.com/Dematom1/argocd-axi/pull/20), [#24](https://github.com/Dematom1/argocd-axi/pull/24), [#29](https://github.com/Dematom1/argocd-axi/pull/29)); workflow resubmit can duplicate work without retry identity (catalog review evidence below); a misspelled flag swallowed as a value once triggered a dangerous stop ([argo-workflows-axi #1](https://github.com/Dematom1/argo-workflows-axi/pull/1)). **How to verify:** run repeated identical writes with one retry key and prove only one effect; prove preview is non-mutating, confirmation is required, multi-target/writable use is opted into, and malformed flags fail before credentials or network access.
- [ ] **P7 — Session integration and skill:** Offer opt-in SessionStart **and** SessionEnd hooks with install/status/uninstall; persist only necessary command memory as `last_session`; protect session state with a lock plus atomic same-directory write/rename. Ship a generated skill and a CI-enforced generator `--check`. **Why:** session memory needed SessionEnd and `last_session` ([datadog-axi #27](https://github.com/Dematom1/datadog-axi/pull/27), [argocd-axi #31](https://github.com/Dematom1/argocd-axi/pull/31)); concurrent writers lost records until locked ([argo-workflows-axi #29](https://github.com/Dematom1/argo-workflows-axi/pull/29)); CodeRabbit caught partial settings/session-file writes ([argocd-axi #31](https://github.com/Dematom1/argocd-axi/pull/31)); generated skill drift should fail CI. **How to verify:** use temporary agent settings/home; test install, status, uninstall, repeated install, malformed settings preservation, simultaneous session ends, mode/atomic replacement, `last_session`, generated-skill `--check`, and CI invocation.
- [ ] **P8 — Content first:** A bare invocation presents concise live status and the most useful next action; if configuration or a target is required, state that fact truthfully and direct the user to setup. **Why:** no-argument CLI should show useful content rather than a generic help screen ([AXI principles](https://github.com/kunchenguid/axi#the-10-principles)). **How to verify:** run with no args in configured, unconfigured, empty, and unavailable environments; check content and exit behavior.
- [ ] **P9 — Scope-preserving hints:** Every next-step hint must preserve all selected scope and filter flags, safely quote values, and retain bounds; do not suggest a command that silently changes target. **Why:** lost org/site and namespace/filter values caused wrong-scope hints ([datadog-axi #22](https://github.com/Dematom1/datadog-axi/pull/22), [#29](https://github.com/Dematom1/datadog-axi/pull/29); [argo-workflows-axi #19](https://github.com/Dematom1/argo-workflows-axi/pull/19), [#26](https://github.com/Dematom1/argo-workflows-axi/pull/26)). **How to verify:** for every command with a hint, use explicit and environment-derived scopes, filters, unusual shell characters, and limits; assert the copyable command keeps them all.
- [ ] **P10 — Focused help:** Every command/subcommand has concise focused `--help` showing purpose, flags/defaults, examples, and valid next commands. **Why:** generic nested help obscured usable command paths ([datadog-axi #23](https://github.com/Dematom1/datadog-axi/pull/23)); help itself must remain TOON-decodable ([argocd-axi #21](https://github.com/Dematom1/argocd-axi/pull/21)). **How to verify:** invoke `--help` at root and every nested command; assert focused content, documented defaults, decodable data, and no credential/network calls.

## Commands & safety

- [ ] Writes are absent unless the product needs them. Each write has a non-mutating preview, explicit `--confirm`, one selected target by default, and an explicit writable-target opt-in; every repeated/retried write is deduplicated using a stable retry key. **Why:** [argocd-axi #20](https://github.com/Dematom1/argocd-axi/pull/20), [#24](https://github.com/Dematom1/argocd-axi/pull/24), [#29](https://github.com/Dematom1/argocd-axi/pull/29). **How to verify:** end-to-end dry-run/apply checks across absent/present confirmation, target defaults, opt-in, and duplicate retries.
- [ ] Parse arguments strictly at the boundary: reject unknown flags, bad enum/list values, and missing values; do not interpret an unknown `--long-flag` as another option's value. **Why:** [argo-workflows-axi #1](https://github.com/Dematom1/argo-workflows-axi/pull/1), [datadog-axi #17](https://github.com/Dematom1/datadog-axi/pull/17). **How to verify:** parser tests include unknown flags in operand position, `--flag=value`, legitimate `-5`/`-v` values, empty filters, and no-side-effect failures.
- [ ] Before shipping, run every command and nested help path against a deterministic fake/stub service; document which checks require a real account. **Why:** response-shape and operational-error mistakes survived happy-path testing ([argo-workflows-axi #11](https://github.com/Dematom1/argo-workflows-axi/pull/11); [datadog-axi #11](https://github.com/Dematom1/datadog-axi/pull/11)). **How to verify:** the committed test plan lists every row, each row has an observed result, and no unrun row is marked passed.

## Sessions & skill

- [ ] Hook installation is opt-in, reports missing/installed/stale state, preserves unrelated agent settings, and supports uninstall without deleting unrelated hooks. **Why:** malformed hook groups caused partial installation and unsafe in-place settings writes ([argocd-axi #31](https://github.com/Dematom1/argocd-axi/pull/31)). **How to verify:** isolated-home lifecycle tests cover malformed groups, reruns, status, and exact preservation of unrelated entries.
- [ ] Session persistence uses a lock for concurrent writers and an atomic temp-file-plus-rename write; it records the minimum useful summary and exposes the current directory's last completed session as `last_session`. **Why:** [argo-workflows-axi #29](https://github.com/Dematom1/argo-workflows-axi/pull/29), [datadog-axi #27](https://github.com/Dematom1/datadog-axi/pull/27). **How to verify:** parallel session-end processes retain every record; a reader sees old or new valid JSON only; inspect payload for absence of command arguments/secrets.
- [ ] Generate the shipped skill from source and fail CI when `--check` detects drift. **Why:** the first-tool review found that `npm test` omitted CLI smoke coverage and that help interception hid the SDK's built-in command ([search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1)); generated skill drift should be checked by the same CI gate. **How to verify:** modify generated output in a temp copy and show `--check` fails, then run it clean in CI.

## Setup & credentials

- [ ] Print concrete setup guidance from the tool itself; include a doctor/status command that identifies each missing prerequisite and the next exact action. **Why:** auth/setup reviews found guides that failed to print after context lookup errors or omitted usable login syntax ([argocd-axi #19](https://github.com/Dematom1/argocd-axi/pull/19), [#1](https://github.com/Dematom1/argocd-axi/pull/1)). **How to verify:** in a clean isolated home, run setup/status with each prerequisite missing and assert a truthful actionable result without a stack trace.
- [ ] Accept credentials through environment variables, corresponding `_FILE` variables, or the platform credential command; never build a tool-specific vault/keychain as the only credential path. Do not print or log secrets. **Why:** browser/keychain auth added setup complexity and portability constraints ([datadog-axi #5](https://github.com/Dematom1/datadog-axi/pull/5); [search-console-axi #2](https://github.com/Dematom1/search-console-axi/pull/2)). **How to verify:** test each source independently, precedence, missing/unreadable files, redaction, and that no secret reaches stdout/stderr/logs.

## Update

- [ ] Preserve the standard SDK `update` command and make its managed-by detection truthful: distinguish package-manager/source-managed installs from self-updatable installs and show the correct next step without overwriting another manager's files. **Why:** the SDK update command was hidden by intercepting help in the first GA4/Search Console scaffold ([search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1)); its review also emphasized managed update behavior. **How to verify:** test installed-by-npm, package manager, source checkout, and unknown provenance; assert update help remains discoverable and no unmanaged file changes occur.

## CI & platform

- [ ] Run CI on Linux and macOS and make the README platform badge list only platforms actually tested and supported. Pin actions to immutable full commit SHAs and set `persist-credentials: false` when executing dependency code. **Why:** Linux/macOS support and truthful Windows exclusion required follow-up ([argo-workflows-axi #30](https://github.com/Dematom1/argo-workflows-axi/pull/30); [datadog-axi #31](https://github.com/Dematom1/datadog-axi/pull/31)); CodeRabbit caught persisted checkout credentials ([search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1)). **How to verify:** inspect the OS matrix, run every matrix job, compare badge to passing support claims, and inspect each checkout action.
- [ ] CI runs build, lint/format, tests, packaged-binary smoke tests, and generated-skill `--check`; release-please PRs receive required checks. **Why:** release-bot PRs initially missed CI until app-token workflow changes ([argocd-axi #14](https://github.com/Dematom1/argocd-axi/pull/14), [argo-workflows-axi #16](https://github.com/Dematom1/argo-workflows-axi/pull/16), [datadog-axi #14](https://github.com/Dematom1/datadog-axi/pull/14)); package-only and entrypoint smoke gaps surfaced on the new-tool PR ([search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1)). **How to verify:** confirm a release PR and package-only PR trigger required checks; run the built package's no-args/help/version tests.

## Docs/VISION

- [ ] Commit a project `VISION.md` defining user, scope/non-goals, expected behavior, platform/auth support, write policy, and deferred capabilities before implementation grows. **Why:** catalog admission expects a product boundary and source-backed principles review ([AXI VISION](https://github.com/kunchenguid/axi/blob/main/VISION.md)). **How to verify:** reviewer checks each user-visible feature and claimed platform/auth mode against VISION; discrepancies are corrected before release.
- [ ] Document install, setup, credentials, permissions/scopes, commands, output/truncation, safety gates, platform support, and troubleshooting; keep the generated skill and README aligned. **Why:** authentication and install misunderstandings prompted documentation follow-ups ([argocd-axi #15](https://github.com/Dematom1/argocd-axi/pull/15), [#19](https://github.com/Dematom1/argocd-axi/pull/19); [datadog-axi #15](https://github.com/Dematom1/datadog-axi/pull/15)). **How to verify:** clean-machine walkthrough from README alone; compare documented command behavior with live `--help` and generated skill.

## Release & publish

- [ ] Configure release-please from conventional commits, npm trusted publishing (OIDC; no long-lived publish token), and a human `axi-approve` step for staged npm releases; release jobs are serialized, retry-safe, and report the exact staged version. **Why:** staged publishing and explicit approval required multiple release follow-ups ([argo-workflows-axi #3](https://github.com/Dematom1/argo-workflows-axi/pull/3), [#7](https://github.com/Dematom1/argo-workflows-axi/pull/7), [#13](https://github.com/Dematom1/argo-workflows-axi/pull/13); [datadog-axi #3](https://github.com/Dematom1/datadog-axi/pull/3), [#10](https://github.com/Dematom1/datadog-axi/pull/10), [#13](https://github.com/Dematom1/datadog-axi/pull/13)). **How to verify:** dry-run release workflow, inspect OIDC permissions and npm provenance, test rerun for published and staged versions, and exercise approval with the exact package/version.
- [ ] Release bot bypasses are narrowly scoped to verified same-repository bot-only PRs and never skip checks for a PR containing human changes. **Why:** bot exemptions were tightened after cross-repository and package-only bypasses were identified ([argocd-axi #23](https://github.com/Dematom1/argocd-axi/pull/23); [datadog-axi #20](https://github.com/Dematom1/datadog-axi/pull/20); [search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1)). **How to verify:** workflow tests cover trusted release bot, external bot, human-authored PR, and human commit added to bot PR.

## Process (no-mistakes, CodeRabbit, test rows)

- [ ] Route each implementation PR through no-mistakes; retain its full public intent, change/risk/test/pipeline sections and pipeline attestation. **Why:** repository-required validation is not equivalent to an unrecorded local run ([datadog-axi #2](https://github.com/Dematom1/datadog-axi/pull/2); [argocd-axi #2](https://github.com/Dematom1/argocd-axi/pull/2); [argo-workflows-axi #2](https://github.com/Dematom1/argo-workflows-axi/pull/2)). **How to verify:** PR shows the required check and complete pipeline record for the current head.
- [ ] Resolve every actionable CodeRabbit finding or document a specific evidence-backed decline; rerun review after fixes and ensure no unresolved correctness/security findings remain. **Why:** review surfaced real target-loss, malformed-response, session-race, and hook-file integrity defects ([datadog-axi #29](https://github.com/Dematom1/datadog-axi/pull/29), [#32](https://github.com/Dematom1/datadog-axi/pull/32); [argo-workflows-axi #29](https://github.com/Dematom1/argo-workflows-axi/pull/29); [argocd-axi #31](https://github.com/Dematom1/argocd-axi/pull/31)). **How to verify:** inspect review threads including inline comments; each actionable thread is resolved or has a justified maintainer disposition.
- [ ] Run every row in the test/validation plan; record exact command, result, and evidence, and label non-live simulation honestly. **Why:** an untested OAuth real-provider path was explicitly disclosed rather than claimed as live ([search-console-axi #2](https://github.com/Dematom1/search-console-axi/pull/2)). **How to verify:** compare the plan's rows against run output and PR report; no row is silently skipped or marked passed from a mock.
- [ ] Never resolve a review thread until its fix commit is on the PR head, and re-check open threads and the head SHA immediately before merging. **Why:** threads were resolved and the PR merged while the fix commit existed only in a local branch, so the release shipped without both fixes ([argo-workflows-axi #31](https://github.com/Dematom1/argo-workflows-axi/pull/31)). **How to verify:** for each resolved thread, find the commit on the PR head that changes the cited lines; merge with the verified head SHA pinned.

## Repo onboarding (GitHub settings/rulesets/secrets via Terraform)

- [ ] At repository creation, provision GitHub settings, rulesets/required checks, Actions permissions, environments, and needed secrets via Terraform; no hand-configured-only prerequisite. **Why:** otherwise an apparently complete first PR can lack required checks, permissions, or publishing secrets. **How to verify:** Terraform plan/apply owns the repo configuration; inspect state and a newly created repository to confirm required rules and secrets/environment wiring.
- [ ] Configure the no-mistakes-required ruleset/check and release workflow identity/token together; verify required checks cannot be skipped by changed-path filters or bot identity assumptions. **Why:** package-only PRs could leave required checks pending and bot-authored PRs could conceal human changes ([search-console-axi #1](https://github.com/Dematom1/search-console-axi/pull/1); [datadog-axi #5](https://github.com/Dematom1/datadog-axi/pull/5)). **How to verify:** create test PRs for source-only, package-only, release bot, external bot, and bot PR with human commit; all required jobs appear and behave as intended.

## Catalog readiness

- [ ] Before requesting catalog admission, pin an exact published version/tag and conduct an independent source review at that pin against all ten principles; cite inspected components and disclose every unmet principle. **Why:** the catalog requires evidence from the exact package, not intent or README claims ([AXI VISION](https://github.com/kunchenguid/axi/blob/main/VISION.md); [catalog contribution guide](https://github.com/kunchenguid/axi/blob/main/CONTRIBUTING.md)). **How to verify:** reproduce the pinned package/tag, check its CLI/help and representative paths, and attach a per-principle review with source locations and limitations.
- [ ] Include a complete catalog entry (name, owner, description, repository, version/revision, evidence, and any principle exception) and satisfy current contribution/admission rules. **Why:** catalog entries are intended to be pinned, independently evidenced, and explicit about exceptions ([AXI catalog](https://github.com/kunchenguid/axi/blob/main/catalog.yaml); [AXI VISION](https://github.com/kunchenguid/axi/blob/main/VISION.md)). **How to verify:** validate the entry against `catalog.yaml` schema, run repository docs/catalog generation and checks, and confirm every factual claim points to source at the pin.
